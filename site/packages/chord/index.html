这个包是什么What this package ischord 是 Pi 新架构的底座：一个facet 宿主把小的功能单元（facet）按依赖顺序装配、激活、热重载和释放；facet 之间只通过有类型的服务交流，而服务可以在同一进程里，也可以跨传输在另一个进程里；服务暴露的状态是复制状态——提供方用普通的赋值修改，chord 算出最小的 JSON delta 发给每个订阅者。另有 ./context（取消与调用范围的值）、./delta（独立的变更追踪器）和 ./node（用 esbuild 打包插件、带 SHA-256 校验地加载）。chord is the foundation of Pi's new architecture: a facet host assembles small units of functionality (facets) in dependency order, activates them, hot-reloads them and disposes them; facets talk only through typed services, which can live in the same process or in another one across a transport; the state services expose is replicated state — the provider changes it with plain assignments and chord computes the minimal JSON delta for every subscriber. Around that sit ./context (cancellation and call-scoped values), ./delta (a standalone change tracker) and ./node (bundling plugins with esbuild and loading them with SHA-256 verification).

共 8,817 行 TypeScript，唯一的运行时依赖是 esbuild，不依赖任何其他 pi 包。使用者：durable（41 个文件）、coding-agent（26 个文件）、server（7 个文件）、client（2 个文件）、env（2 个文件）、protocol（2 个文件）——coding-agent 里用到的都在 src/experimental/ 下。8,817 lines of TypeScript; the only runtime dependency is esbuild, and it depends on no other pi package. Users: durable (41 files), coding-agent (26 files), server (7 files), client (2 files), env (2 files), protocol (2 files) — everything coding-agent uses lives under src/experimental/.

03Infra

Facet 的一代：装配与激活A facet generation: assembly and activation#

一句话结论Takeawayactivate() 依次经过 setup → assembling → connecting → activating → active：先同步调用每个 facet 的 setup(env) 收集它要用和要提供的服务，再整体校验（一个服务一个提供者、模式一致、无环），按拓扑顺序给出激活顺序，等所有远程绑定 ready，最后按顺序运行各自的 onActivate。释放按相反顺序进行。activate() goes setup → assembling → connecting → activating → active: each facet's setup(env) runs synchronously to collect what it uses and provides, the whole graph is validated (one provider per service, matching modes, no cycles), a topological sort gives the activation order, every remote binding is awaited until ready, and each onActivate runs in order. Disposal runs in reverse.

要点Key points

  • setup 必须同步：返回 Promise 会被拒绝。这让依赖图在任何异步工作开始前就是完整、可校验的。setup must be synchronous: returning a Promise is rejected. That makes the dependency graph complete and checkable before any async work starts.
  • 校验错误都带着服务和 facet 的名字："is provided by both …"、"… but no facet provides it"、"Facet dependency cycle: …"。Validation errors name the service and facets: "is provided by both …", "… but no facet provides it", "Facet dependency cycle: …".
  • 任何一步失败，#terminate() 释放已经建好的部分，把原错误和清理错误合成一个 AggregateError 抛出。If any step fails, #terminate() disposes what was built and throws the original error together with cleanup errors as one AggregateError.
  • 每个 facet 内部，own() 登记的释放函数也按逆序执行——后建的先拆。Within each facet, the disposals registered with own() also run in reverse — last built, first torn down.

工作原理How it works

  1. FacetKernel.activate()：对每个 facet 调 setup，得到 FacetShape（requires / provides）。FacetKernel.activate(): call setup for each facet to get its FacetShape (requires / provides).
  2. #resolveExternalServices() 读宿主的 serviceSources 目录 → validateFacets() → topologicalOrder()。#resolveExternalServices() reads the host's serviceSources catalogues → validateFacets() → topologicalOrder().
  3. 绑定服务 → 等待 ready() → 按 #activationOrder 逐个 activate()。Bind services → await ready() → activate() each facet in #activationOrder.

04Infra

热重载Hot reload#

一句话结论Takeawayreload(facets) 用新实现替换一组已激活的 facet，而使用方手里的句柄不断开：先 setup 候选并检查它们的 requires / provides 与旧的完全相同，再在旧实现仍然服务请求时激活候选，然后切换（单例重新绑定、远程提供者 replace()），再退役旧 facet、连接新的 keyed 实例。reload(facets) replaces a set of active facets with new implementations without disconnecting anyone's handles: set up the candidates and check their requires / provides are exactly the same, activate them while the old ones still serve, then cut over (rebind singletons, replace() remote providers), retire the old facets and connect the new keyed instances.

要点Key points

  • 形状不变是硬性要求：重载不能增删依赖或提供的服务（"must preserve its service requirements and provisions"）。改形状需要新的一代。Unchanged shape is a hard rule: a reload cannot add or remove dependencies or provisions ("must preserve its service requirements and provisions"). Changing the shape needs a new generation.
  • 切换之前失败：释放候选，宿主回到 active，旧实现继续工作。切换之后失败：整个代被中止（"Facet reload failed after cutover"）。A failure before the cutover disposes the candidates and returns to active with the old code still working. After the cutover, the whole generation is aborted ("Facet reload failed after cutover").
  • 句柄是代理：每次访问都通过 ServiceSlot.resolve() 取当前实现，所以重新 bind 之后已有句柄立即用上新代码。Handles are proxies: every access resolves the current implementation through ServiceSlot.resolve(), so after a rebind existing handles use the new code immediately.
  • keyed 实例按 generation 区分：重载后旧实例关闭，新实例以新的 generation 出现，观察者会看到 closed 再 spawned。Keyed instances are generation-specific: after a reload the old ones close and new ones appear with new generations, so observers see closed then spawned.

工作原理How it works

  1. 宿主先用 loader 的 load() 拿到候选的 LoadedFacets。The host first gets the candidate LoadedFacets from a loader's load().
  2. host.reload(loaded.facets)；失败就释放候选。host.reload(loaded.facets); on failure, dispose the candidate.
  3. 成功后再释放退役的那一代 LoadedFacets，旧代码随之可以被回收。After success, dispose the retired LoadedFacets, so the old code can be collected.

05Infra

服务、句柄与 ContextServices, handles and Context#

一句话结论Takeaway服务令牌是 defineService<T>(id, options?)。默认是远程服务：它的成员只能是 (…json, Context) => Promise<json> 或 ReplicatedState<json>，这样同一份接口既能在进程内用，也能跨传输用；{ local: true } 的服务可以是任意 TypeScript 形状，但永远不出本进程。提供方式有单例（provide / use）与 keyed（provideMany / observe）两种。A service token is defineService<T>(id, options?). By default it is remote: its members must be (…json, Context) => Promise<json> or ReplicatedState<json>, so one interface works both in-process and across a transport; a { local: true } service can have any TypeScript shape but never leaves the process. Provision is either singleton (provide / use) or keyed (provideMany / observe).

要点Key points

  • 远程约束在类型层面检查（RemoteServiceContract<T>），运行时在边界上再校验一次（validateRemoteServiceImplementation）。The remote constraint is checked in the type system (RemoteServiceContract<T>) and again at runtime at the boundary (validateRemoteServiceImplementation).
  • coding-agent 的实验服务就是例子：pi.transcript 只有一个 state: ReplicatedState<ConversationView>；pi.local.presentation-ui 是本地服务。coding-agent's experimental services are examples: pi.transcript has just state: ReplicatedState<ConversationView>; pi.local.presentation-ui is a local service.
  • 每个调用最后一个参数都是 Context：它携带取消信号和调用范围的值。awaitWithContext() 取消时只拒绝等待者，不会中止正在进行的工作。Every call's last argument is a Context: it carries cancellation and call-scoped values. awaitWithContext() on cancellation rejects only the waiter, never the work in progress.
  • ID 以 $chord. 开头的服务是保留的：那是 chord 自己的控制调用。Service IDs starting with $chord. are reserved: that prefix is chord's own control calls.

工作原理How it works

  1. export const Models = defineService<Models>("pi.models")——类型和令牌同名。export const Models = defineService<Models>("pi.models") — the type and the token share a name.
  2. 在 facet 的 setup 里：const models = env.use(Models)；在 onActivate 或之后调用 await models.select(m, ctx)。In a facet's setup: const models = env.use(Models); from onActivate on, call await models.select(m, ctx).
  3. 取消：const { context, cancel } = withCancel(parent)，把 context 传下去。Cancellation: const { context, cancel } = withCancel(parent) and pass context down.

跨进程的服务Services across processes#

一句话结论Takeaway提供方一侧由 RemoteServiceProvider 执行调用、管理订阅，createRemoteServiceEndpoint() 处理 $chord.service 控制调用（catalogue、subscribe、unsubscribe）；使用方一侧的 createRemoteServiceBinding() 给出与本地一样的外观。中间的传输只要实现 invoke 与 subscribe，外层信封由应用决定。On the provider side, RemoteServiceProvider runs calls and manages subscriptions, and createRemoteServiceEndpoint() serves the $chord.service control calls (catalogue, subscribe, unsubscribe); on the consumer side, createRemoteServiceBinding() gives the same facade as a local service. The transport in between only implements invoke and subscribe; the outer envelope is up to the application.

要点Key points

  • 订阅更新有 6 种：state（某成员的一批 op）、reset、unavailable、replaced、spawned、closed。Subscription updates come in 6 kinds: state (a batch of ops for one member), reset, unavailable, replaced, spawned, closed.
  • 背压：每个订阅最多 100 个待发更新；第 101 个到来时整个队列换成一个 reset，带着当前完整快照和新的 sequence 基线。Backpressure: at most 100 pending updates per subscription; when the 101st arrives the whole queue becomes one reset with a full current snapshot and new sequence baselines.
  • 普通 state 更新绝不允许跳号；传输适配器必须保持快照 / reset / 更新的顺序，不能丢批。An ordinary state update never permits a gap; transport adapters must keep snapshot / reset / update order and must not drop batches.
  • 能跨边界的错误只有 8 个 service_* 码，例如 service_not_found、service_stale_instance、service_invalid_value。Only 8 service_* codes may cross the boundary, e.g. service_not_found, service_stale_instance, service_invalid_value.

工作原理How it works

  1. 提供方：用宿主的 provider 创建 createRemoteServiceEndpoint(provider)，把收到的调用交给它。Provider: create createRemoteServiceEndpoint(provider) from the host's provider and hand it incoming calls.
  2. 使用方：实现 RemoteServiceTransport；再实现一个 RemoteServiceSource（catalogue() + open()），在 open() 里用 createRemoteServiceBinding({ services, transport })，作为宿主的 serviceSources 传入——coding-agent 的 experimental/services/connection.ts 就是这样做的。Consumer: implement RemoteServiceTransport; then a RemoteServiceSource (catalogue() + open()) whose open() uses createRemoteServiceBinding({ services, transport }), passed to the host in serviceSources — as coding-agent's experimental/services/connection.ts does.
  3. 同进程测试：createLoopbackServiceTransport(provider) 直接把两边接起来。In-process tests: createLoopbackServiceTransport(provider) wires both sides directly.

复制状态Replicated state#

一句话结论Takeawayenv.replicatedState(initial) 返回一个可变的复制状态。change(ctx, draft => …) 在一个 Draft 上做普通的赋值，chord 算出 op、换上新的不可变版本、sequence 加一，然后发给两类订阅者：内部的精确订阅（同步拿到每个版本的 op，用来编码给远端）和公开的 subscribe()（每个订阅串行收到完整值）。env.replicatedState(initial) returns a mutable replicated state. change(ctx, draft => …) makes plain assignments on a Draft; chord computes the ops, swaps in the new immutable revision, increments the sequence and publishes to two kinds of subscriber: internal exact subscriptions (every revision's ops, synchronously, for encoding to remotes) and public subscribe() (complete values, serialized per subscription).

要点Key points

  • 一次 change() 恰好发布一个原子版本；回调抛错时值和 sequence 都不变；没有产生 op 就不发布。A successful change() publishes exactly one atomic revision; if the callback throws, value and sequence stay unchanged; no ops, no publication.
  • 回调必须同步，也不能在回调里再次 change（"cannot be changed reentrantly"）。The callback must be synchronous and cannot change the state again from inside ("cannot be changed reentrantly").
  • 公开订阅最多积压 100 个值，溢出时只留最新的——所以公开的 sequence 可能跳号；异步回调里应读捕获的 value 而不是 state.value。Public subscriptions keep at most 100 pending values and keep only the newest on overflow — so public sequences may skip; async callbacks should read the captured value, not state.value.
  • 远端副本严格按序：update 要求 sequence 正好是上一个加一，否则清空并抛出 "update sequence has a gap"。The remote replica is strictly ordered: update requires exactly the previous sequence plus one, else it clears and throws "update sequence has a gap".

工作原理How it works

  1. status.change(ctx, d => { d.output += "done\n"; d.count += 1 })。status.change(ctx, d => { d.output += "done\n"; d.count += 1 }).
  2. 内部：tracker.beginChange() → 回调 → prepare() → adopt() → publisher.publish(value, ops, ctx)。Internally: tracker.beginChange() → callback → prepare() → adopt() → publisher.publish(value, ops, ctx).
  3. 远端：ReplicatedStateReplica.hydrate(seq, ops) 建立基线，之后每个 update(seq, ops) 用 applyImmutable 重放。Remote: ReplicatedStateReplica.hydrate(seq, ops) sets the baseline, then each update(seq, ops) replays with applyImmutable.

JSON deltaJSON deltas#

一句话结论Takeaway./delta 定义 7 种 op：r 替换根、s 设置、d 删除、a 字符串追加、t 字符串去头、p 数组 splice、m 数组重排。追踪器为字符串挑最省的写法（追加；或去头加追加——适合滚动日志；否则整体设置），op 太多时折叠成一个 r。线上格式 WireOp 只多两种压缩：路径编号和省略路径。./delta defines 7 ops: r replace root, s set, d delete, a string append, t string front-truncate, p array splice, m array permute. The tracker picks the cheapest string form (append; or truncate plus append — good for rolling logs; else a set) and folds into one r when there are too many ops. The wire format WireOp adds only two compressions: path ids and omitted paths.

要点Key points

  • 超过 4,096 个 op 时折叠成 ["r", 整个根]；去头 + 追加的重叠扫描最多 65,536 个字符。More than 4,096 ops fold into ["r", whole root]; the truncate-plus-append overlap scan covers up to 65,536 characters.
  • 路径在第二次使用时才定义编号（["#", id, path]），因为定义比路径本身还长，只用一次的路径内联更省。A path gets an id on its second use (["#", id, path]), because a definition costs more than the path; paths used once stay inline.
  • 省略路径只在同一批内有效；跨批的唯一状态是编号字典，遇到 r 就清空——每个 r 都是一个恢复点。Omitted paths only work within a batch; the only cross-batch state is the id dictionary, cleared at every r — each r is a recovery point.
  • 值是不可变、结构共享的：没变的子树在版本之间共用，不做防御性拷贝也不冻结。Values are immutable and structurally shared: unchanged subtrees are reused across revisions, with no defensive copies and no freezing.

工作原理How it works

  1. const tracker = track(initial)；const change = tracker.beginChange()；改 change.state。const tracker = track(initial); const change = tracker.beginChange(); mutate change.state.
  2. const prepared = change.prepare()；tracker.adopt(prepared)；副本用 applyImmutable(prepared.base, prepared.ops)。const prepared = change.prepare(); tracker.adopt(prepared); a replica uses applyImmutable(prepared.base, prepared.ops).
  3. 跨边界：encoder().encode(ops) → 发送 → decoder().decode(wire)。Across a boundary: encoder().encode(ops) → send → decoder().decode(wire).

打包与加载插件Bundling and loading plugins#

一句话结论TakeawaybundleFacetPackage() 读插件包 package.json 里的 chord.facets，用 esbuild 打成 .cjs（peer 依赖和 chord 本身保持 external），写出 chord-facets.json 清单，每个入口带 SHA-256 完整性值。createFacetBundleLoader() 加载时先校验哈希，再用 node:vm 的 compileFunction 编译，只允许 require 清单里声明过的 external。bundleFacetPackage() reads chord.facets from a plugin's package.json, bundles it with esbuild into .cjs (peer dependencies and chord itself stay external) and writes a chord-facets.json manifest with a SHA-256 integrity value per entry. createFacetBundleLoader() verifies the hash at load time, compiles with node:vm's compileFunction, and lets the code require only externals the manifest declares.

要点Key points

  • 输出先写到临时目录，再整体改名替换；旧目录先挪到 .old-<uuid>，替换失败就挪回来——加载方永远看不到写了一半的包。Output goes to a temporary directory and is renamed into place; the old directory is moved to .old-<uuid> first and moved back if the swap fails — a loader never sees a half-written bundle.
  • 入口文件名带内容哈希（facet-<短哈希>-[hash].cjs），不同版本不会互相覆盖。Entry file names carry content hashes (facet-<short hash>-[hash].cjs), so versions never overwrite each other.
  • 也可以把整个包读成一个 artifact（readFacetBundleArtifact）再加载，适合把插件作为一个值传递。A bundle can also be read as one artifact (readFacetBundleArtifact) and loaded from that, handy for passing a plugin around as one value.

工作原理How it works

  1. 构建：bundleFacetPackage({ packagePath, outdir })。Build: bundleFacetPackage({ packagePath, outdir }).
  2. 加载：createFacetBundleLoader({ manifestPath, entry, resolveExternal? }) → load() 得到 LoadedFacets；完整性校验默认开启（verifyIntegrity）。Load: createFacetBundleLoader({ manifestPath, entry, resolveExternal? }) → load() gives LoadedFacets; the integrity check is on by default (verifyIntegrity).
  3. 交给 host.reload(loaded.facets) 热替换，或作为新一代的 facets。Hand them to host.reload(loaded.facets) for a hot swap, or use them for a new generation.
