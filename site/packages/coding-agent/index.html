这个包是什么What this package ispi-coding-agent 是产品本身：pi 命令、SDK 与 RPC 服务器都从这里出来。它把 pi-agent-core 的通用 Agent 装配成一个编码智能体——加上会话树（JSONL）、内置工具、扩展系统、设置与资源加载，以及 interactive / print / json / rpc 四种运行模式。pi-coding-agent is the product: the pi command, the SDK and the RPC server all come from here. It turns the generic Agent from pi-agent-core into a coding agent — adding the session tree (JSONL), built-in tools, the extension system, settings and resource loading, and four run modes: interactive, print, json and rpc.

位于最上层：依赖 pi-agent-core、pi-ai、pi-tui，以及 pi-mcp、pi-codemode、chord。这里的核心类是 AgentSession（一次会话）和 AgentSessionRuntime（可替换会话的宿主）。The top layer: depends on pi-agent-core, pi-ai, pi-tui, plus pi-mcp, pi-codemode and chord. The central classes are AgentSession (one session) and AgentSessionRuntime (the host that can swap sessions).

01pi-coding-agent

模块结构Module structure#

一句话结论Takeaway四个入口共用一个内核：cli.ts（pi 命令）与 rpc-entry.ts 都进入 main.ts；index.ts 是 SDK 入口。真正的逻辑在 core/，三种 UI 形态在 modes/。Four entry points share one core: cli.ts (the pi command) and rpc-entry.ts both enter main.ts; index.ts is the SDK entry. The real logic lives in core/; the three UI shapes live in modes/.

要点Key points

  • core/agent-session.ts 是 core/ 里最大的文件（interactive 模式的 interactive-mode.ts 更大）：它持有 Agent、SessionManager、ExtensionRunner 与模型运行时，并负责重试、压缩和排队消息。core/agent-session.ts is the largest file in core/ (only interactive mode's interactive-mode.ts is bigger): it owns the Agent, the SessionManager, the ExtensionRunner and the model runtime, and handles retry, compaction and queued messages.
  • rpc-entry.ts 只做一件事：调用 main(["--mode", "rpc", …])，并通过 ./rpc-entry 导出路径对外提供。rpc-entry.ts does one thing: call main(["--mode", "rpc", …]); it is published as the ./rpc-entry export path.
  • src/extensions/ 里是随包附带的内置扩展（MCP、codemode、tool-search 等），走的是和用户扩展相同的 API。src/extensions/ holds the bundled built-in extensions (MCP, codemode, tool-search …); they use the same API as user extensions.

工作原理How it works

  1. pi → setupCli() → main(argv)：解析参数、决定模式、建会话。pi → setupCli() → main(argv): parse args, pick a mode, build the session.
  2. SDK 用户直接调用 createAgentSession() 或 createAgentSessionRuntime()，跳过 CLI。SDK users call createAgentSession() or createAgentSessionRuntime() directly and skip the CLI.
  3. 所有模式拿到的都是同一个 AgentSessionRuntime，区别只在输入输出方式。Every mode receives the same AgentSessionRuntime; they differ only in how input and output flow.

CLI 启动流程CLI start-up#

一句话结论Takeawaymain() 是一条直线：先处理一次性命令，再解析参数、决定模式、跑迁移、读设置、建 SessionManager、确认项目信任、创建 runtime，最后把 runtime 交给 RPC、interactive 或 print 模式。main() is a straight line: handle one-shot commands, then parse args, resolve the mode, run migrations, load settings, create the SessionManager, settle project trust, create the runtime, and hand it to RPC, interactive or print mode.

要点Key points

  • resolveAppMode() 同时看参数和 stdin/stdout 是否为 TTY：-p、或 stdin / stdout 任一不是 TTY 时走 print，--mode json / --mode rpc 显式指定。resolveAppMode() looks at both args and whether stdin/stdout are TTYs: -p, or a non-TTY stdin or stdout, means print; --mode json / --mode rpc are explicit.
  • runMigrations(cwd) 在任何会话读写之前执行，迁移旧的认证文件、会话目录、工具目录、按键配置与扩展布局。runMigrations(cwd) runs before any session I/O and migrates old auth files, session directories, tool dirs, keybinding config and extension layout.
  • 项目信任（ProjectTrustStore）决定是否加载 <cwd>/.pi/ 下的设置与扩展；它在创建 runtime 之前确定。Project trust (ProjectTrustStore) decides whether settings and extensions under <cwd>/.pi/ load at all; it is settled before the runtime is created.
  • prepareInitialMessage() 把命令行里的文字、@file 附件和管道输入合成第一条用户消息。prepareInitialMessage() combines command-line text, @file attachments and piped stdin into the first user message.

工作原理How it works

  1. parseArgs(argv) → resolveAppMode(parsed, stdinIsTTY, stdoutIsTTY)。parseArgs(argv) → resolveAppMode(parsed, stdinIsTTY, stdoutIsTTY).
  2. createSessionManager()：按 --no-session / --fork / --session / --resume / --continue 选择内存会话、分叉、打开指定会话或选择器。createSessionManager(): in-memory, fork, open a given session or show the picker according to --no-session / --fork / --session / --resume / --continue.
  3. createAgentSessionRuntime() 构造 services 与第一个 AgentSession。createAgentSessionRuntime() builds the services and the first AgentSession.
  4. 按模式分派：runRpcMode(runtime)、new InteractiveMode(runtime).run() 或 runPrintMode(runtime, …)。Dispatch by mode: runRpcMode(runtime), new InteractiveMode(runtime).run() or runPrintMode(runtime, …).

AgentSession 如何装配 AgentHow AgentSession wires the Agent#

一句话结论TakeawayAgentSession 不改写 Agent 的循环，而是把每个钩子接到编码场景的实现上：streamFn 走 ModelRuntime，transformContext 交给扩展的 context 事件，beforeToolCall / afterToolCall 交给 tool_call / tool_result 事件，subscribe() 把每条消息写进会话文件。AgentSession does not rewrite the Agent loop; it plugs each hook into a coding-specific implementation: streamFn goes through ModelRuntime, transformContext to the extensions' context event, beforeToolCall / afterToolCall to the tool_call / tool_result events, and subscribe() writes every message into the session file.

要点Key points

  • 事件先交给扩展、再交给 UI 监听器（_handleAgentEvent），所以扩展总能先看到并改写。Events reach extensions before UI listeners (_handleAgentEvent), so extensions always see and rewrite first.
  • 一次运行结束后由 _handlePostAgentRun() 决定是否再跑一次：可重试错误 → 退避重试；超出上下文或超过阈值 → 压缩；还有排队消息 → continue()。After a run, _handlePostAgentRun() decides whether to go again: retryable error → back off and retry; context overflow or over threshold → compact; queued messages → continue().
  • 扩展的 tool_call 处理器出错时，工具调用会被阻止，而不是放行。If an extension's tool_call handler throws, the tool call is blocked rather than allowed.
  • turn_end 是边界点：扩展可以在两轮之间往会话里追加条目。turn_end is a boundary: extensions may append entries to the session between turns.

工作原理How it works

  1. createAgentSession()（sdk.ts）构造 new Agent({ streamFn, convertToLlm, … })，再把它交给 new AgentSession(…)。createAgentSession() (sdk.ts) builds new Agent({ streamFn, convertToLlm, … }) and passes it to new AgentSession(…).
  2. AgentSession 构造时安装其余钩子并 agent.subscribe()。The AgentSession constructor installs the remaining hooks and calls agent.subscribe().
  3. prompt(text)：运行中按 streamingBehavior 转成 steer() / followUp()，空闲时开始新一轮。prompt(text): while running it becomes steer() / followUp() per streamingBehavior; when idle it starts a run.
  4. 运行结束 → _handlePostAgentRun() → 必要时再次 continue()，直到 agent_settled。Run ends → _handlePostAgentRun() → continue() again if needed, until agent_settled.

AgentSessionRuntime：替换会话AgentSessionRuntime: replacing the session#

一句话结论Takeaway/new、/resume、/fork、导入都不是在原会话上“改”，而是整个换掉：先问扩展是否取消，再关闭旧 AgentSession，用新的 SessionManager 和新的 services 建一个新 AgentSession，最后让 UI 和扩展重新绑定。/new, /resume, /fork and import never edit the current session; they replace it: ask extensions whether to cancel, shut down the old AgentSession, build a fresh one with a new SessionManager and fresh services, then let the UI and extensions rebind.

要点Key points

  • session_before_switch / session_before_fork 返回 { cancel: true } 时，整个替换中止，方法返回 { cancelled: true }。If session_before_switch / session_before_fork returns { cancel: true }, the replacement stops and the method returns { cancelled: true }.
  • 旧会话按 abort → session_shutdown → dispose() 的顺序关闭；扩展的 TUI 组件被同步卸下。The old session closes in the order abort → session_shutdown → dispose(); extension TUI widgets are detached synchronously.
  • 扩展中捕获的旧 ctx 在替换后失效；需要在替换后继续工作的扩展应使用 withSession 回调里的新 ctx。A captured ctx goes stale after replacement; extensions that must keep working should use the fresh ctx passed to withSession.

工作原理How it works

  1. switchSession() / newSession() / fork() 先触发对应的 session_before_* 事件。switchSession() / newSession() / fork() first emit the matching session_before_* event.
  2. 打开或新建 SessionManager（fork 时 newSession({ parentSession }) 记录来源）。Open or create a SessionManager (fork records the origin via newSession({ parentSession })).
  3. createAgentSessionServices() + createAgentSessionFromServices() 建新会话。createAgentSessionServices() + createAgentSessionFromServices() build the new session.
  4. 替换 runtime 内的 session / services / diagnostics，再 rebindSession()。Swap session / services / diagnostics inside the runtime, then rebindSession().
